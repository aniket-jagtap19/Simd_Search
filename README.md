# Assignment 8: Comparative Study of OpenMP and MPI, with an HPC Mini-Project

Two independent parts live in one repository:

| Part | What | Where | Technology |
|---|---|---|---|
| **1. Mini-project: SimdSearch** | Exact Top-K similarity search (cosine / Euclidean), serial baseline vs OpenMP | `part1_simdsearch/` | C++17, OpenMP, CMake |
| **2. OpenMP vs MPI exercise** | Matrix-vector multiplication: serial, OpenMP, MPI | `part2_matvec/` | C++17, OpenMP, MPI |
| Analysis | Benchmark -> CSV -> graphs / tables | `scripts/`, `results/` | Python, NumPy, pandas, Matplotlib |
| Dashboard (optional) | Interactive front end that calls the C++ binary | `dashboard/` | Streamlit |
| Report | All required sections A-I | [`docs/REPORT.md`](docs/REPORT.md) | Markdown |

> **Naming note.** "SimdSearch" is only a project name. **No explicit SIMD code is written** and none is claimed.
> The compiler report for the scoring loops shows scalar SSE2 arithmetic only (details in the report, section C).

MPI is optional at build time: without an MPI installation, Part 1 and the serial/OpenMP matrix-vector code still build and run.

## 3. Build

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

| CMake option | Default | Meaning |
|---|---|---|
| `-DENABLE_MPI=AUTO\|ON\|OFF` | `AUTO` | `AUTO`: build MPI targets if MPI is found; `ON`: fail if missing; `OFF`: skip |
| `-DBUILD_TESTING=ON\|OFF` | `ON` | build the automated tests |
| `-DSIMDSEARCH_NATIVE=ON` | `OFF` | add `-march=native` (not portable; the build flags are recorded in benchmark metadata) |
| `-DMPIEXEC_EXTRA_FLAGS="--oversubscribe"` | empty | extra `mpiexec` flags for the ctest MPI tests (Open MPI on machines with few cores) |

Binaries (in `build/`): `part1_simdsearch/{simdsearch,bench_search,test_simdsearch}`,
`part2_matvec/{bench_matvec_omp,test_matvec,matvec_mpi,test_matvec_mpi}` (the last two only with MPI).

## 4. Run the automated tests

```bash
cd build && ctest --output-on-failure
```

Without MPI you get 2 test suites (SimdSearch unit tests, matrix-vector serial/OpenMP). With MPI, 5 more
(`matvec_mpi_np{1,2,3,4,8}`). Each MPI test is launched with `--expect-np N` and **fails if the real world size is not N**,
which protects against a broken launcher that would otherwise make every process a silent singleton (see Troubleshooting).

## 5. Part 1: SimdSearch

```bash
B=build/part1_simdsearch
$B/simdsearch search --n 50000 --dim 128 --k 10 --metric cosine --threads 1,2,4        # synthetic data
$B/simdsearch search --data data/sample_dataset.bin --query-index 17 --k 5 --metric euclidean
$B/simdsearch search --data data/sample_dataset.csv --query-file data/sample_query.csv --k 5
$B/simdsearch generate --n 100000 --dim 64 --seed 7 --out my_data.bin                  # .csv extension => text
$B/simdsearch search --json ...                                                         # machine-readable (dashboard uses it)
$B/simdsearch info                                                                      # hardware/software environment
```

Options: `--n --dim --seed --query-seed --query-index --query-file --data --k --metric cosine|euclidean --threads LIST --mode serial|omp|both --repeats --warmup --show --json --config FILE`.

Sample output (`data/sample_output_cosine.txt`, real run):

```
SimdSearch  metric=cosine  n=12  dim=6  k=5  source=data/sample_dataset.csv  query=file:data/sample_query.csv

rank   id         cosine_similarity
1      2          0.840625704
2      10         0.830379564
...
verification: OpenMP results identical to serial (IDs exact, scores within 1e-9)
```

**Ranking rules.** Cosine similarity: highest first. Euclidean distance: lowest first. Equal scores: smaller vector ID first (so results are identical for any thread count).
**Zero-norm vectors.** Cosine with a zero vector (data or query) is defined as `0.0` (never NaN). Euclidean distance is unaffected.
**Validation.** `K >= 1` (K > n is clamped to n); dimension match; NaN/Inf rejected in queries and datasets; malformed, truncated or ragged files rejected with a message; exit code 2 on invalid input.
**Dataset file formats.** Binary `SIMDSRC1` (8-byte magic, `uint64 n`, `uint64 dim`, then `n*dim` little-endian float32) or CSV (one vector per line, `#` comments).

### Benchmarks

```bash
build/part1_simdsearch/bench_search --config configs/simdsearch_quick.cfg     # seconds
build/part1_simdsearch/bench_search --config configs/simdsearch_full.cfg      # full grid, ~1 minute
# override anything:  --sizes 1000,10000 --dims 64 --ks 10 --metrics cosine --threads 1,2,4,8 --repeats 9
```

Every parallel result is verified against the serial result **before** its timing is written; a mismatch aborts that row with exit code 1.

## 6. Part 2: matrix-vector multiplication (serial / OpenMP / MPI)

```bash
build/part2_matvec/bench_matvec_omp --config configs/matvec_assignment.cfg --threads 1,2,4,8
mpiexec -n 4 build/part2_matvec/matvec_mpi --config configs/matvec_assignment.cfg --expect-procs 4
```

Outputs: `results/matvec_omp.csv` (serial + OpenMP) and `results/matvec_mpi.csv` (appended per `mpiexec` call; delete it before a fresh sweep).
Two MPI variants are timed, because they answer different questions:

* `mpi_full`: **every run** scatters `A`, broadcasts `x`, computes, gathers `y` (end-to-end, comparable to a one-shot call).
* `mpi_resident`: `A` was distributed once beforehand; each run broadcasts `x`, computes and gathers `y` (repeated multiplications such as iterative solvers).

The OpenMP version needs neither, because threads share `A` in memory.

## 7. Don't oversubscribe: how the runners protect you

All benchmark programs compare the requested workers with the CPUs this process may use (affinity mask and container CPU quota).
By default they **skip** counts above that (`SKIP threads=8 > 4 available CPU(s)`); the MPI program refuses to start (exit 3).
`--allow-oversubscribe` (script: `ALLOW_OVERSUBSCRIBE=1`) runs them anyway, **marks every such row `oversubscribed=1`** in the CSV, and the plots draw
those points hollow inside a red "oversubscribed" zone. Such rows measure scheduling overhead, not scaling.

## 8. One command for everything

```bash
scripts/run_all.sh                       # build, test, benchmark (strict: only worker counts <= CPUs), plot
ALLOW_OVERSUBSCRIBE=1 scripts/run_all.sh # also run 2/4/8 workers on a small machine (flagged)
THREADS="1 2 4 8 16" PROCS="1 2 4 8 16" SEARCH_CONFIG=configs/simdsearch_full.cfg scripts/run_all.sh
```

Results: `results/*.csv`, `results/*_meta.json` (hardware, compiler, flags, OpenMP/MPI runtime, statistic, repetitions),

## 11. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `Could NOT find OpenMP` | Install `libomp` (macOS) or a GCC/Clang with OpenMP; pass `-DOpenMP_ROOT=...` |
| CMake prints `MPI : NOT built` | MPI not found. Install it, or ignore if you only need Part 1 / OpenMP. Force an error with `-DENABLE_MPI=ON` |
| **Every MPI rank reports "rank 0 of 1" / `MPI processes: 1` printed N times** | Launcher/library mismatch. Observed on Ubuntu 24.04 with the `mpich` package: its `libmpich` is built against PMIx but its Hydra `mpiexec` speaks another PMI, so each process silently becomes a singleton. Use Open MPI (`sudo apt install openmpi-bin libopenmpi-dev`, then `sudo update-alternatives --config mpi`), or another consistent MPICH build. Check with a hello-world that prints rank and size. |
| `test_matvec_mpi: expected N processes but ... has M` | Same problem, detected by the `--expect-np` guard |
| Open MPI: "not enough slots available" | Add `--oversubscribe` (`-DMPIEXEC_EXTRA_FLAGS="--oversubscribe"`, or `MPIEXEC_FLAGS="--oversubscribe"` for the script). Only for correctness tests or flagged runs |
| Open MPI: "mpiexec has detected an attempt to run as root" (containers) | `export OMPI_ALLOW_RUN_AS_ROOT=1 OMPI_ALLOW_RUN_AS_ROOT_CONFIRM=1` or add `--allow-run-as-root` |
| `refusing to run: N MPI processes ... oversubscribed` (exit 3) | Intentional. Use fewer processes or add `--allow-oversubscribe` |
| Speedups around 1.0 or below for every thread count | Check `nproc`. With 1 available CPU parallel speedup is impossible. Run on a multi-core machine |
| Noisy timings (large `stddev_ms`) | Shared VM / laptop power saving. Close other programs, use more `--repeats`, compare `min_ms`, pin threads: `OMP_PROC_BIND=close OMP_PLACES=cores` |
| `error: out of memory` | Reduce `--n`/`--dim` (a dataset needs `n*dim*4` bytes) |
| Dashboard: "C++ binary not found" | Build first, or set `SIMDSEARCH_BIN=/path/to/simdsearch` |
| Dashboard warns about `width="stretch"` | Upgrade Streamlit (`pip install -U "streamlit>=1.50"`) |
